# 上下文路由（Context Router · 地图的地图）

> **本文件是文档体系的唯一入口索引。** 任何会话开始先读它，再按需加载其他文档。
> 设计参考 Codex/Claude Code 的上下文分层：规则层常驻，其余索引化、按需检索，源码注解默认冷存储。

## 加载策略（三条铁律）
1. **⚖️ 宪法长驻**：`开发宪法.md` 每次会话都应在上下文（行为红线）。
2. **🧭 本路由常查**：定位文件时读，不含文档正文。
3. **🗄️ 代码解说默认不加载**：`代码解说/` 是源码镜像，**默认冷存储**；只有当任务明确涉及某模块（如"改 JsInteration"）时，才读取对应的那一个文件。禁止为了"了解全貌"而批量读代码解说。

## 二、场景 → 加载 路由表

| 任务场景 | 加载文档（按序，最小化） |
|---|---|
| 刚接手，第一次读系统 | 路由 → 宪法 → 手册(第0~2节) → README |
| 改某个 Java 文件 | 宪法(5B) → 代码解说/`<该文件>.md`（仅此一个） → 相关速查表章节 → 演化日志 |
| 改前端 JS/HTML | 宪法(5B) → 代码解说/`前端_*.md`（相关者） → 手册前端章 → 演化日志 |
| 改 Node-RED 流 | 宪法(5B) → 代码解说/`NodeRED_节点注解.md` → 速查表 → 演化日志 |
| 排障：灯不亮 | 手册排障 → 速查表灯光段 → 代码解说/`JsInteration.md`+`HopeJs.md` → 日志(B) |
| 排障：空调失控 | 速查表空调段 → 代码解说/`NodeRED_节点注解.md` → 日志(B-10) |
| 排障：白屏 | 手册事实1 → 代码解说/`Constant.md`+`NettyServerHandler.md` → 日志(B-03) |
| 标记新 bug | 工作日志(B模板) → 宪法(4.1 现场vs潜在) |
| 修已标记 bug | 宪法(4.2~4.9) → 该 B 上下文 → 对应代码解说 → 速查表 → 演化日志 |
| 部署/运维 | 手册第6章 → 演化日志(版本矩阵) → 宪法(6.5 回退) |
| 不确定读什么 | 回本路由查；仍不确定只读宪法+路由，问用户 |

## 三、上下文污染防护
1. 读源码优先读代码解说（已提炼），不读原始大 `.java` 文件。
2. **代码解说默认不加载**（见顶部铁律3）；批量读代码解说 = 反模式。
3. 任务完成释放非长驻文档，不保留过时副本。
4. 演化日志是唯一真相源；宪法版本唯一，改了 sync 长驻上下文即可。
