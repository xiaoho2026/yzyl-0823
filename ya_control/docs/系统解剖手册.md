## 0. 一句话理解这个系统

一台**壁挂中控屏（Android 设备，横屏）**运行一个单 Activity App，内部只有一个全屏 `WebView`，
加载本地 H5 控制界面；H5 通过 JS Bridge 调 App，App 再通过 **MQTT / TCP / UDP / 门牌** 与中控屏本机的
**Node-RED 中控逻辑**和**各类楼控硬件**（灯光 / 空调 / 继电器 / 门牌）通信。
中控逻辑（设备协议翻译）不在 App 里，而在中控屏本机运行的 **Node-RED 流（`亚中.json`）** 里。

```
[壁挂中控屏 Android 设备]
 ├─ App (ya_control)  —— 只有一个全屏 WebView
 │    └─ H5 控制界面（由 PC 部署工具经 TCP 下发到 html/ 目录）
 │         └─ JS Bridge (android.*) → App → MQTT/TCP/UDP/门牌
 │
 ├─ Node-RED (亚中.json)  —— 中控逻辑：把 MQTT 指令翻译成各品牌硬件私有协议
 │    └─ 内含 aedes MQTT Broker (端口 39201)
 │
 └─ 硬件：非凡士灯光 / 空调面板 / 联克继电器 / 巨典继电器+门牌 / 视频矩阵
```

## 1. 三个必须知道的核心事实（先刻进脑子）

1. **前端不在 App 里，由外部下发。**
   `app/src/main/assets/html/` 是**空目录**。App 默认 `Constant.WEB` 指向 `index_android.html`，
   但该文件不存在于前端工程里。真实前端入口是 `总控选择.html`。
   → 所以**部署时必须用 PC 工具（`中控上传程序.exe`）同时下发 `conf.ini` 把 `web` 改成 `总控选择.html`**，
   否则 App 解压前端后仍加载 `index_android.html` → 白屏。
   （前端工程见 `ya_control-html/`，与原始 `亚中中控控制优化/` 逐字节一致。）

2. **中控逻辑（协议翻译）在 Node-RED 里，不在 App 里。**
   App 只负责"把 H5 的 `{control,child}` 发到 MQTT `/jyc/control`"，真正的设备协议转换由
   `亚中.json` 里的 `解析网络协议` 函数完成。改设备行为要先看 Node-RED 流，再看 App。

3. **有两套独立部署物，缺一不可。**
   - `ya_control`（Android App，Android Studio 构建）
   - `亚中.json`（Node-RED 流，在中控屏本机 Node-RED 里部署）
   - 还有 `中控上传程序.exe`（PC 侧下发工具，不在本仓库，单独存放）
   三者版本要配套，否则协议对不上。

## 2. 推荐阅读顺序（不要跳，按这个走）

### 第一步：建立全局观（1 小时）
1. 读 `README.md` 全文（架构、目录、通信、速查表、已知问题）
2. 读本文档第 0~1 节
3. 在纸上画出"图0"那条链路（App ↔ Node-RED ↔ 硬件）

### 第二步：读 App 代码（半天）
按依赖顺序，不要从 MainActivity 硬啃：
```
1. Constant.java          —— 所有 IP/端口/topic/路径常量，先记住
2. JycApplication.java    —— 启动做了什么（SDK、读 conf.ini、启 Netty）
3. JsInteration.java      —— H5 能调的 4 个 JS 接口（relay/sync/updateHopeLightBarColor/sendMqtt）
4. mqtt/JycMqttClient.java —— 订阅哪 5 个 topic，收到后怎么进 App
5. mqtt/JycService.java   —— MQTT 前台服务
6. netty/Netty.java + DecoderHandler + NettyServerHandler + NettyClientHandler
                             —— 与 PC 工具/门牌的 TCP/UDP 通道
7. MainActivity.java      —— UI/WebView/Handler 消息号（11/12/13/200/666/-1）
8. api/HopeJs.java        —— 灯带（adb 写节点）
9. utils/*                —— Ini4jUtil/UiUtil/AdbUtil/Crc16Util/Self/SwitchReceiver/APKVersionCodeUtils
```
> 阅读时把每个类"它接收什么、发出什么"记在旁边，建立模块间的消息流向。

### 第三步：读前端（半天）
```
1. js/utils.js            —— host/led.control/face.* 等全局接口（注意 led.control 拼写坑）
2. js/element.js          —— 组件库（addEmn/addHvac/addBottom/...）
3. js/index_10.js         —— 10寸主逻辑：setData 回显、楼层总控、视频矩阵、getChilds
4. js/index_4.js          —— 4寸屏（与 index_10 镜像，差异见 README 5.2）
5. 挑 1~2 个 html 页（如 5楼总经理.html、总控选择.html）看组件怎么拼
```

### 第四步：读 Node-RED 中控流（1 天）
`亚中.json` 是 1702 行 JSON，不要逐行读，按"节点名"搜着读：
```
1. 搜 "aedes broker"        —— 找到本地 MQTT broker（端口 39201）
2. 搜 "mqtt in"             —— 找到 /jyc/control、/jyc/getData、/jyc/close、/jyc/heartbeat
3. 搜 "解析网络协议"         —— 找到设备协议转换核心函数（灯光/空调/联克）
4. 搜 "数据添加到内存"       —— 找到状态存内存+写 save.json
5. 搜 "crontab"             —— 找到定时场景（6点冷光/12点午休/20点暖光）
6. 搜 "继电器编号"           —— 找到联克继电器楼层配置
```
> 配合 `docs/设备点号速查表.md` 一起看，每个点号段对应什么设备一目了然。

### 第五步：读部署工具（2 小时，可选但建议）
`Debug/中控上传程序.exe` 是二进制（Windows），无法在 macOS/Android 编译。
用 `strings`/十六进制方式只能看 UI 文本和协议字段（见 README 9.6）。
重点理解：**它下发工程 zip（type 2）/ 配置（type 4）/ APK（type 3）**，与 App `NettyServerHandler` 对应。

## 3. 模块解剖：每个部件"接收什么 / 发出什么"

| 部件 | 接收 | 发出 | 备注 |
|---|---|---|---|
| H5 页面 | 用户点击 | `android.sendMqtt/relay/sync/updateHopeLightBarColor` | JS Bridge |
| `JsInteration` | H5 调用 | MQTT `/jyc/control`、巨典广播、adb | 4 个接口 |
| `JycMqttClient` | MQTT `/jyc/control`、`/jyc/feedback`、`/jyc/heartbeatback` | `setData()` 注入 H5、更新心跳 | 订阅 5 topic |
| `NettyServerHandler` | TCP（PC工具 type1/2/3/4） | 解压工程/装APK/写conf.ini | 部署通道 |
| `NettyClientHandler` | 门牌 TCP | ping/opendoor | 每2s心跳 |
| `Netty.udpClient` | — | UDP 组播上报设备信息 | 225.0.0.20:55555 |
| `HopeJs` | 灯带控制 | adb 写 `/sys/.../led_con_h` | 绕开 Node-RED |
| Node-RED `解析网络协议` | MQTT `/jyc/control` | TCP 到硬件（灯光/空调/继电器） | 中控大脑 |
| Node-RED `数据添加到内存` | `/jyc/control` | 写 `save.json` | 持久化 |

## 4. 关键契约（开发/联调必须守的"接口"）

### 4.1 JS Bridge 契约（H5 ↔ App）
| JS 调用 | App 处理 | 去向 |
|---|---|---|
| `window.android.sendMqtt(obj)` | `JsInteration.sendMqtt` | MQTT `/jyc/control` |
| `window.android.relay(obj)` | `JsInteration.relay` | 巨典广播 `com.judian.broadcast.relay.control` |
| `window.android.sync(str)` | `JsInteration.sync` | 启动 MQTT 服务 |
| `window.android.updateHopeLightBarColor(obj)` | `JsInteration.updateHopeLightBarColor` | HopeJs 灯带 |
| App → H5：`setData(json)` | `JycMqttClient` | H5 `window.setData` 回显 |

### 4.2 MQTT 主题契约
| 方向 | Topic | 内容 |
|---|---|---|
| H5→中控 | `/jyc/control` | `{control, child}` |
| 中控→H5 | `/jyc/control`（回显！非 feedback） | 内存全量状态 |
| 中控→H5 | `/jyc/feedback` | 反馈 |
| H5→中控 | `/jyc/getData` | 拉全量状态 |
| H5→中控 | `/jyc/heartbeat` | 心跳 |
| 中控→H5 | `/jyc/heartbeatback` | 心跳应答 |
| H5→中控 | `/jyc/close` | 清状态 |
| H5→中控 | `/jyc/reboot` | 重启 |
| 小程序→中控 | `/yzyl/control`（云 broker） | type==2 取 data |

### 4.3 TCP 部署通道契约（App `NettyServerHandler`）
| type | 含义 | App 动作 |
|---|---|---|
| 1 | 取配置 | 回传 `conf.ini` 当前值 |
| 2 | 工程 zip | 解压到 `html/` |
| 3 | APK | 按设备型号静默安装 |
| 4 | 配置 JSON | 覆写 `Constant` 字段（含 `web`） |

### 4.4 设备点号契约（见 `docs/设备点号速查表.md`）
灯光 `1xxxxx` / 空调 `4/5/6/7xxxxxx` / 联克继电器 `8xxxxxx` / 场景特殊点 `5/6/7/8/9xxxxxxxxx`

## 5. 新手最常踩的 5 个坑（先预警）

1. **白屏**：部署前端后没改 `conf.ini` 的 `web` → App 仍找 `index_android.html`。（见第1节事实1）
2. **`led.control` 拼写**：H5 `utils.js` 调 `updateZhyLightBarColor`，但 App 端方法名是
   `updateHopeLightBarColor`（Zhy≠Hope）→ 灯带控制调用失败。改一端即可，但改哪端要想清。
3. **`opendoor` 未实现**：H5 `.opendoor` 点击调 `window.android.opendoor()`，但 App 没这个方法。
   物理按键3 走的是门牌 TCP `opendoor`（`SwitchReceiver`，但未注册）。
4. **明文 HTTP**：`networkSecurityConfig` 允许明文，会议后端 `meeting-test.scasia-core.com:8099` 是 HTTP。
   换 https 要同步改网络安全配置。
5. **两套继电器混淆**：联克（`8xxxxxx`，Node-RED TCP）vs 巨典（App adb 广播）是两套独立系统，别搞混。

## 6. 开发 / 运维工作流

### 6.1 改前端（H5）
1. 改 `ya_control-html/` 里的 html/js
2. 用 PC 工具 `中控上传程序.exe` 把目录打包下发（type 2）
3. 改入口需同步下发 `conf.ini`（type 4）改 `web`

### 6.2 改 App（Java）
1. Android Studio 打开 `ya_control/`
2. 改代码 → `Build APK` → 用 PC 工具下发（type 3）静默安装
3. **注意**：若改了 `NettyServerHandler` 报文格式，必须同步改 PC 工具 exe 才能联调

### 6.3 改中控逻辑（Node-RED）
1. 在中控屏本机 Node-RED 编辑器导入/修改 `亚中.json`
2. 改设备点号/协议必须同步更新 `docs/设备点号速查表.md`
3. 部署后验证 `save.json` 与硬件响应

### 6.4 运维排障清单
- **屏不亮 / 白屏**：查 `conf.ini` 的 `web` 是否指向真实入口；查 `html/` 是否下发成功
- **点灯无反应**：查 Node-RED `解析网络协议` 该点号段；查非凡士网关 `172.17.63.202:23432` 通否
- **空调失控**：查 `空调编号` 表 IP:port；查 `tcps` 队列；查网关连通
- **MQTT 连不上**：查中控屏本机 aedes broker 39201；查 `Constant.MQTT_HOST`
- **App 反复重启**：查 `MainActivity` 权限被拒 `killProcess`；查心跳超 5min 自动重启 Cron
- **日志记录**：工作记录在 `docs/工作日志.md`

## 7. 词汇表（新手词典）

| 词 | 含义 |
|---|---|
| 中控屏 | 壁挂 Android 设备，运行本 App |
| Node-RED | 可视化流编程工具，本系统用它做设备协议翻译 |
| aedes | Node-RED 内置的 MQTT Broker 实现 |
| 灯带 | 氛围灯，由 App 走 adb 写 sys 节点控制（HopeJs） |
| 门牌 | 门口屏/门禁，走 TCP 到 `172.16.50.27:13580` |
| 巨典 | 继电器/门牌系统厂商，App 用广播 `com.judian.broadcast.*` 交互 |
| 联克 | 另一品牌继电器，由 Node-RED 走 TCP 下发 |
| 非凡士 | 灯光系统厂商，网关 `172.17.63.202:23432` |
| 工程包 | 前端 H5 的 zip，由 PC 工具下发 |
| conf.ini | 运行时配置（MQTT/门牌/首页/设备名），可经部署工具覆盖 |
| save.json | Node-RED 把设备状态持久化到中控屏本机 `/home/cotodo/save.json` |
