# 设备点号速查表（开发 / 排障地图）

> 本表是"点号 → 设备 → 协议 → 硬件"的全景映射，来自 `亚中.json` 的 `解析网络协议` 函数与
> `空调编号`/`继电器编号` 等节点。开发新页面、排障"点了没反应"时，先查这里定位点号属于哪类设备。
> 点号是 H5 与中控之间的"设备地址"，前端页面里写 `control="xxxxx"` / `child="a-b"` 就是它。

---

## 1. 点号分段总览

| 点号段 | 设备类型 | 处理节点（Node-RED） | 下发通道 | 状态回显 |
|---|---|---|---|---|
| `100001 – 199999` | 非凡士灯光 | `解析网络协议(非凡士/空调)` | TCP `172.17.63.202:23432` | `/jyc/control` |
| `4000001 – 4999999` | 空调面板（老协议） | 同上 | `tcps` 队列 → TCP | 同上 |
| `5000001 – 5999999` | 空调面板 | 同上 | `tcps` 队列 → TCP | 同上 |
| `6000001 – 6999999` | 董事长新风 | 同上 | `tcps` 队列 → TCP | 同上 |
| `700000001 – 799999999` | 多联机空调（网关） | 同上 | `tcps` 队列 → TCP | 同上 |
| `8000001 – 8999999` | **联克继电器** | `解析网络协议(联克)` | `link_tcps` 队列 → TCP | 同上 |
| `≤ 370` | 继电器类（巨典，点号小） | （App 巨典广播处理） | App `relay` 广播 | 开机强制 false |
| `955xxx` 等 | 场景模式（办公/休息） | H5 本地互锁 + 关联 child | 经 `/jyc/control` | 同上 |

## 2. 特殊场景点号（前端按钮 → 中控）

| 点号 | 含义 | 触发位置 | 中控动作 |
|---|---|---|---|
| `999999999` | 全开 | 楼层总控 `floor-init` | 该楼层所有灯开 |
| `888888888` | 冷光（白光） | `floor-cw1` / 定时6点 | 色温→冷，亮度100 |
| `666666666` | 暖光 | `floor-cw2` / 定时20点 | 色温→暖，关部分 |
| `777777777` | 休息模式 | `floor-mode1` / 定时12点 | 关部分灯 |
| `555555555` | 正常模式 | `floor-mode2` | 恢复默认 |

> 这些点号在 `解析网络协议` 内作为 `if` 条件判断，命中后转成非凡士灯光指令。
> 场景逻辑 = 前端写特殊点号 + Node-RED 条件分支，不在 App。

## 3. 灯光点号结构（`1xxxxx`）

格式：`1` + 楼层(1位?) + 区域/回路编号
- 例：`151927` = 5楼 区域灯光主控制；`151711-151712` = 子回路范围
- 楼层总控：`101000 + 楼层*10000`（如5楼=`151000`）
- 调光：`250000 + 楼层*1000 + i`、`350000 + 楼层*1000 + i`
- 视频矩阵：`10001`（ASCII 数组，"1All."/"1B1." 改首字节）

---

## 4. 空调点号结构（`4/5/6/7xxxxxx`）

| 前缀 | 设备 | 帧格式 | 校验 |
|---|---|---|---|
| `4xxxxx` | 空调面板（老） | Modbus hex：开关/模式/风速/温度 | `crc16Modbus` |
| `5xxxxx` | 空调面板 | 同上，模式/风速编码不同 | `crc16Modbus` |
| `6xxxxx` | 董事长新风 | 开关/风速 hex | `crc16Modbus` |
| `7xxxxxxxxx` | 多联机（网关） | `网关ID+类型+值+空调ID` | `makeCheckSum` |

**空调编号表（固化，来自 `699c9af8` 节点）**：`{IP:port → 面板ID[]}`
- 例：`172.17.63.109:1030` = [2..27]（某楼层空调面板）
- 楼层：1~5 楼 + -1 楼，IP `172.17.63.10x:103x`
- 查询：`定时查询空调` 每 600s 生成 `num+"0300000004"+crc` 入 `querys` 队列
- 下发：`队列解析` 每 1s 从 `tcps[IP:port]` 取队首 → `tcp request`

> 新增空调点位：必须同时在 `空调编号` 节点补 `IP:port → 面板ID` 映射，否则帧无处可发。

---

## 5. 联克继电器点号结构（`8xxxxxx`）

格式：`8` + 楼层(2位) + 设备ID(2位) + 通道(2位)
- 例：`8511001` = 5楼 / 设备11 / 通道01
- 帧：`AAAA0B` + 区域id(`01`) + 设备id(hex) + `050142` + 通道(hex) + (`64`开 / `00`关) + `makeCheckSum`
- 队列：`link_tcps`（每 0.5s 由 `继电器队列发送` 触发，`队列解析` 发 TCP）
- **当前仅固化 -1 楼**：`继电器编号` 节点 `links[-1] = [{"172.17.63.168:1030":[10,11]}]`
- 扩展：在 `继电器编号` 节点补 `links[楼层] = [{IP:port:[设备ID...]}]`

> ⚠️ 联克继电器（Node-RED TCP）与巨典继电器（App adb 广播）是**两套独立系统**，别混淆。

## 7. 定时场景（Node-RED crontab 节点）

| 节点名 | cron | 动作 | 点号范围 |
|---|---|---|---|
| 6点执行 | `00 06 * * *` | 冷光，全开 | `11xxxx`~`15xxxx`（值100） |
| 午休模式 | `00 12 * * *` | 休息 | `12xxxx`（值0） |
| 20点执行 | `00 20 * * *` | 暖光 | `11xxxx`~`15xxxx`（值0，666666666） |
| 18点（如有） | `00 18 * * *` | 见流 | 同上 |

> 逻辑：注入后 `setTimeout` 分5批（1~5s）把各楼层 child 点号批量下发 `/jyc/control`。
> 注释提到"中午12-13点屏蔽雷达、晚8点过道变暖光"——部分逻辑可能未完全实现（见工作日志 bug 标记）。

## 8. 排障决策树（点灯/空调没反应时）

```
点了没反应
├─ 检查 H5 写的点号段（第1节表）
│   ├─ 灯光 1xxxxx → 查非凡士网关 172.17.63.202:23432 通否；查 Node-RED 该分支
│   ├─ 空调 4/5/6/7xxxxx → 查 空调编号表 是否有该 IP:port；查 tcps 队列；查网关
│   ├─ 联克 8xxxxxx → 查 继电器编号 links[楼层] 是否配置；查 link_tcps 队列
│   └─ 巨典继电器 → 查 App relay 广播；查巨典系统
├─ 检查 MQTT 是否通（/jyc/control 能否收到）
│   └─ 查中控屏 aedes 39201；查 Constant.MQTT_HOST
└─ 检查前端是否真发了（android.sendMqtt 是否被调用）
    └─ 查 JsInteration.sendMqtt；查 H5 控制台
```
